# 2026-08-06 开发日志

> 今日完成输入模块迁移收尾、K230 全量接入、模块库交互完善和旧产品兼容矩阵复核。动力、输出和通信模块尚未迁移积木实现。

## 开发流程修复

- 重构桌面开发进程生命周期，直接管理 webpack 和 Electron 子进程。
- 桌面端或控制台退出时主动释放 `8601`，避免下次启动误用旧 bundle。
- 普通启动检测到未知进程占用端口时直接报错，不再静默复用。
- 切换主产品时同步清空 VM 与 Blockly 画布，避免旧产品积木残留。
- 关闭扩展库后触发 Blockly 尺寸重算，恢复工具箱滚轮和可视区域。

## 输入模块迁移

### 基础模块收尾

- 迁移外接 IMU 的 4 个积木，并保留校准积木对普通初始化变量的强制覆盖。
- 迁移 LED 超声波的 7 个积木。
- 修正 RGB 颜色代码生成，将颜色参数输出为 `0xff,0x99,0x66` 形式的三个十六进制通道。

### WonderEcho 与 K230

- 迁移 WonderEcho 的 8 个积木和三组语音菜单。
- 分批迁移 K230 的 127 个积木，覆盖基础控制、人脸、人体、手势、颜色、线条、文字、码识别、目标检测和 MCP 工具配置。
- 增加静态 MCP JSON、Python 标识符、中文颜色名和产品参数菜单格式化能力。
- 增加产品级积木过滤与参数覆盖，同一个 K230 包可按当前产品裁剪积木和菜单。
