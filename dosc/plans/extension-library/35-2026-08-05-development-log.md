# 2026-08-05 开发日志

## 今日结果

今天完成输入传感器第二至第四批迁移，`sensor` 内置产品包从 `1.1.0` 升级到 `1.3.0`。当前共包含 14 个分类、31 个 opcode 和 9 个实际菜单，可直接在 editor 内为支持的 AI 产品添加并测试，无需先发布远程产品包。

## 完成内容

### 第二批：颜色识别与温湿度

- 迁移颜色识别模块和温湿度传感器，共 7 个积木。
- 保持旧版初始化、颜色读取、RGB 读取、温度和湿度读取的 Python 调用。
- 更新产品支持列表、内置快照和回归测试。
- 已提交为 `a401c0c feat(extension): 迁移第二批输入传感器`。

### 第三批：六路巡线

- 迁移六路巡线传感器 6 个积木，包含初始化、单路状态、组合状态、阈值、灰度值和偏差值。
- 复用 `LINE6` 可视化字段，按 `1/2/4/8/16/32` 保存每路位掩码。
- 组合状态生成两位十六进制值，例如 `linefollow6.get_result_data() == 0x15`。
- 对产品能力做去重：AI 机甲麦轮车已有内置六路巡线，因此不重复开放共享模块。

### 第四批：四路巡线

- 迁移普通四路巡线和旋钮四路巡线，共 9 个积木。
- 新增 `ArgumentType.LINE4`、`line4` shadow block 和 `FieldLine4`，贯通 VM、Scratch Blocks、manifest schema 与 Python codegen。
- 四路选择器按 `0x00-0x0f` 限制掩码，每一路可独立选择；第 1、4 路选中为 `0x09`，四路全选为 `0x0f`。
- 普通四路生成 `DEV_LINE_FOLLOW_4` 调用，旋钮四路生成 `DEV_LINE_FOLLOW_4_O` 调用。
- 保留旧版产品边界：不迁移只对 `aiblocks/aiblocksboard` 开放的阈值和灰度积木，也不迁移旧 VM 已注释的积木。

## 四路字段问题修复

人工验收时发现四路组合状态积木只显示空白圆角输入，六路字段正常。代码检查确认产品清单、VM shadow 映射和构建产物均包含 `LINE4`，最终将 `line4` block 改为直接创建 `FieldLine4`，避免依赖字段注册时序。

回归测试新增以下约束：

- 四路值必须规范化为两位十六进制，并限制在 `0x0f` 内。
- 六路原有 `0x3f` 范围保持不变。
- 创建 `line4` block 后必须实际取得 `FieldLine4`，不能只留下空 shadow 外壳。

验收过程中还确认 `npm run desktop` 会复用已经占用 8601 端口的 GUI 开发服务。本次旧服务启动于 10:22，早于 17:02 的最新 Scratch Blocks 构建，因此连续验收实际看到的是旧代码。停止旧服务并重新启动后，人工验收通过。
